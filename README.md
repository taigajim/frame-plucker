# Frame Plucker

After Effects ExtendScript for removing repeated held frames from AI-generated video — Seedance-style clips that are packaged as full-rate video but contain duplicated frames.

The script uses `ffmpeg` to analyze adjacent-frame differences and removes the duplicates it finds, whether they form a steady cadence, a cadence that drifts over the clip, or just a handful of scattered held frames. It creates a shortened clean comp and never overwrites the original footage.

## Requirements

- Adobe After Effects
- `ffmpeg` — the script looks for it on PATH and in common install locations (e.g. Homebrew on macOS, `C:\ffmpeg\bin` on Windows); if it can't find one, it asks you to locate the executable and remembers your choice

Download ffmpeg: [ffmpeg.org/download.html](https://ffmpeg.org/download.html)

## After Effects Setup

Enable scripting access:

1. Open `After Effects > Settings` or `Preferences`.
2. Go to `Scripting & Expressions`.
3. Turn on `Allow Scripts to Write Files and Access Network`.

## Usage

1. Select one file-backed video in the Project panel, or select its layer in a comp.
2. Run `frame-plucker.jsx`.

There is no setup dialog. Frame Plucker reads the frame rate from the selected source, scans the whole clip (up to a built-in safety cap), detects duplicates automatically, and creates a clean comp named after the detected pattern, with a summary marker at frame 0.

Possible outcomes:

- **Clean footage** — no duplicate-frame pattern found: the script tells you the clip plays like genuine full-rate motion and creates nothing.
- **High confidence** — a steady cadence verified across the clip: the clean comp is created directly.
- **Medium confidence** — a cadence that drifts, isolated held frames, or a short clip: the script explains what it found and asks before creating the comp.

## How Detection Works

The probe uses ffmpeg at 160px width with `tblend` difference plus `signalstats` YAVG. The detector estimates a per-clip noise floor, marks duplicate candidates relative to it, and refuses clips whose duplicates don't separate clearly from real motion — low-motion frames are never mistaken for held frames.

Detection then runs in three tiers, strictest first:

1. **Locked cadence** — duplicates repeat at fixed positions (e.g. every 2nd frame). Found via period scoring, verified across clip sections; can extrapolate beyond the analyzed range.
2. **Drifting cadence** — a regular hold rhythm whose phase slips over the clip. Duplicates are removed at their measured positions.
3. **Scattered holds** — no rhythm, but individual frames that are provably duplicates (detached from the motion continuum) are removed one by one.

Freeze holds (6+ identical frames, e.g. a static ending shot) are excluded from cadence analysis, kept in the output, and reported in the result. Guards at every tier reject pauses and quiet-but-moving frames, so genuine footage is left alone.

## Development

Run the dependency-free test suite:

```sh
npm test
```

Regenerate synthetic fixture logs with ffmpeg:

```sh
bash test/make-fixtures.sh
```

Fixture videos are temporary and are not committed; the checked-in artifacts are the captured metric logs under `test/fixtures/`. Two of those logs (`animation-drift.txt`, `seedance2-scatter.txt`) were captured from local real clips and cannot be regenerated by the script — don't delete them.
